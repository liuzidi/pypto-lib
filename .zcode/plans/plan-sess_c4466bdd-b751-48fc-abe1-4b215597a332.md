# C1b Fix Plan — Shape-derived scalar semantics (Option 1)

## Goal
Fix the framework-side bug that makes `mtp_projection_rms` leak stale device memory to output (the doc's explicit PASS target). Leave `proj_a_mm` honestly failing (its scalars are `partition_view` offsets, not derivable from shapes — documented limitation).

## Root cause (confirmed)
`vpto_run.py:402-413` (captured) and `:430-439` (model-py) mark only the **first** non-SPMD index scalar as `"ctx_len"` and set every other to `None`. `setup_main.py:182` then emits `= 0; // FIXME` for each `None`-sem scalar → tensor-view shape collapses → SPMD loop never runs → stale device-memory values (e.g. `rsqrt(eps)=1000.0`) leak to output.

For `mtp_projection_rms` the buggy `main.cpp` is:
```cpp
int64_t v5 = 8;   // ctx_len (wrong scalar, but harmless)
int64_t v6 = 0;   // FIXME  ← should be 8  (dim0 of v1=[%arg5,7168]: 57344/7168)
int64_t v7 = 0;   // FIXME  ← should be 16 (dim0 of v2=[%arg6,1]:    16/1)
```

## Approach — derive each index scalar's value from the `.pto` tensor-view shapes
`parse_pto` already parses every `make_tensor_view %argK, shape = [...]` line (pto_parse.py:86-104) but only uses shapes for the **static** elem-count product, discarding any `%arg`-valued dimension. Extend it to also record, per index scalar, the set of `(tensor_param_name, dim_position)` occurrences where the scalar appears in a tensor's shape. Then in `vpto_run.py`, resolve each such scalar's value from the tensor elem_counts (total / product of the static dims), instead of the "first=ctx_len" heuristic.

## Files to change (3 files, all in the live skill lib)

### 1. `/.claude/skills/vpto-board-validate/lib/pto_parse.py` — add shape→scalar mapping
- Extend `parse_pto` to build a new `info["scalar_dims"]` dict: `{scalar_arg ("%arg5"): [ (ptr_param_name ("v1"), [static_dim_sizes_except_scalar]), ... ]}`.
  - Reuse the existing `make_tensor_view` shape scan loop (lines 86-104). For each tensor param `p`, for each shape entry `s`: if `s` matches `%argN` (an index scalar) rather than a `%cM_index` constant, record `(p["name"], [info["dims"][x] for x in shape if x != s])` under `scalar_dims["%argN"]`.
  - Keep `elem_counts` behavior unchanged (static-only).
- Add a thin helper `derive_scalar_values(info, elem_counts) -> dict` returning `{scalar_param_name ("v6"): int_value}` for each index scalar that has ≥1 tensor-view occurrence whose *other* dims are all static AND the referenced tensor has a known elem_count. Resolution rule: `value = elem_count[ptr_name] // product(other_static_dims)`; if multiple tensors agree, use the first; if they disagree, skip (don't fill, leave a clear FIXME). Scalars with no shape occurrence (e.g. `proj_a_mm`'s offsets, `mtp_projection_rms`'s `%arg4`) get no entry → handled by the existing fallthrough.
- Update the module docstring's `info` shape description to mention `scalar_dims`.

### 2. `/.claude/skills/vpto-board-validate/vpto_run.py` — use derived values
- Import the new helper.
- In **both** the `--captured-dump` branch (lines 402-414) and `--model-py` branch (lines 430-441): replace the "first non-spmd = ctx_len, else None" loop with:
  1. Compute `derived = derive_scalar_values(info, ec)` where `ec` = `cmeta["elem_counts"]` (captured) or `model_meta.get("elem_counts")` (model-py) merged with `info["elem_counts"]`.
  2. For each index scalar param `p`: if `p["name"]` in `derived` → `scalar_sem` entry `"derived"` (a new sentinel); else fall back to existing heuristic *only* for the first ctx_len (keep SPMD block_num special-case in setup_main untouched).
  3. Add the derived values into `load_vals` under a new key, e.g. `load_vals["derived"] = derived` (dict of name→int).
- Keep Mode A (golden-lib) branch untouched — it already has correct semantics.

### 3. `/.claude/skills/vpto-board-validate/lib/setup_main.py` — emit derived values
- In `gen_main_cpp`'s scalar loop (lines 165-182): add an arm **before** the `else` (and after the ctx_blocks arm):
  ```python
  elif sem == "derived" and s["name"] in (load_vals.get("derived") or {}):
      v = load_vals["derived"][s["name"]]
      param_decls.append(f"    {scal_type} {s['name']} = {v};  // derived: tensor-view dim")
  ```
  Scalars still missing (no shape occurrence / no elem_count / disagreement) fall through to the existing `= 0; // FIXME` — **including `proj_a_mm`'s v4-v7**, which is the documented honest outcome.
- Extend `compute_scalar_comment` (pto_parse.py:259) with an `elif sem_name == "derived": return "derived: 从 .pto tensor-view shape 推导的张量维大小"` so the comment is meaningful (optional polish; the setup_main arm above already sets its own comment).

## What this does NOT fix (documented)
- **C1a** (`rms_norm` family, 5 rows): pypto inner-kernel hardcoded-shape + UB-address bug — routed to pypto, out of scope.
- **`proj_a_mm`** (2 rows): scalars are `partition_view` offsets (`arith.muli %arg4, %c1024` etc.), not tensor dims → not derivable from shapes. Stays at `= 0; // FIXME`. The doc already hedges this as "PASS or true-precision FAIL depending on cube-kernel precision at correct indices" — option 1 leaves it failing, consistent with the doc's lower-bound expectation. A deeper fix (reading `args_dump.json` scalar `value` field) is deliberately deferred.
- **C3** (~45 rows, same `scalar_sem` bug): this fix only helps the subset whose scalars are tensor-view dims. Kernels whose scalars are loop bounds/offsets (the majority of C3) are not helped by option 1 and remain routed to a future option-2-style args_dump fix. The doc's C3 is broader than C1b; I am only claiming the C1b row (`mtp_projection_rms`).
