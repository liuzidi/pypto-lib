# Plan: `test_for_dsv4/` — Self-Contained DSV4 VPTO Golden Test Suite

## Goal

Create `test_for_dsv4/` (mirroring `test_for_ptoas_extracted/` structure) containing:
- All 101 distinct DSV4 `.pto` kernel files
- One `dsv4_golden_lib.py` with a `BUILDERS` dict + `run_case(name)` that generates **random inputs + CPU torch golden** for each kernel (no GM dump, no NPU capture)
- Auto-generated `run_<kernel>/` dirs with `golden.py`, `main.cpp`, `launch.cpp`, `vpto/run.sh`
- One-command runner: `setup_all.sh` → `run_all.py`

This completely bypasses the `enable_dump_args=2` all-zeros bug because golden data is generated on CPU via torch.

## dsv4_golden_lib.py — the core golden library

Structure (mirrors qwen3_decode_golden_lib.py but uses torch):

```python
import torch
import numpy as np

# DSV4 model constants (from models/deepseek_v4_pro/config.py)
DECODE_BATCH = ...
DECODE_SEQ = ...
HIDDEN = ...
# etc.

def make_bf16(generator, count, scale=0.05): ...   # torch.randn → bf16 → uint16
def make_fp32(generator, count, scale=0.05): ...
def make_i8(generator, count, scale=0.05): ...     # for quantized kernels

BUILDERS = {
    "rms_norm": build_rms_norm,
    "comb_sinkhorn": build_comb_sinkhorn,
    "merge_norm": build_merge_norm,
    "kv_score_proj": build_kv_score_proj,
    # ... 101 entries
}

def run_case(name):
    meta = load_case_meta()
    generator = rng()
    ints = load_int32_assignments()
    buffers, golden = BUILDERS[name](meta, generator, ints)
    write_buffers(meta, buffers)
    write_golden(meta, golden)
```

Each `build_<kernel>(meta, generator, ints)` function:
1. Reads buffer shapes/dtypes from `meta` (parsed from main.cpp)
2. Generates random inputs with seeded RNG
3. Computes golden output using torch (matching the kernel's computation)
4. Returns `(buffers_dict, golden_dict)`

## Implementation Steps

### Step 1: Collect .pto files (101)
Script `collect_pto.py`:
- Scan all `build_output/phase5_dump_*/ptoas/*.pto`, dedupe by basename
- Copy all to `test_for_dsv4/.pto/`

### Step 2: Write `dsv4_golden_lib.py`
This is the main work. Launch **4-6 parallel subagents**, each handling ~15-20 kernels:
- Each subagent reads the kernel's `.pto` (to understand signature: ptr types, shapes, scalars)
- Reads the corresponding model `.py` (for the computation logic — e.g. how rms_norm is computed)
- Writes `build_<kernel>(meta, generator, ints)` returning random inputs + torch-computed golden
- Uses `validation_runtime.py` helpers (load_strided_2d, write_buffers, etc.)

### Step 3: Copy framework files
- `golden/validation_runtime.py` — copy from test_for_ptoas
- `golden/compare.py` — copy from test_for_ptoas
- `lib/pto_parse.py` / `lib/setup_main.py` / `lib/setup_vpto.py` — symlink to skill's versions

### Step 4: Write setup scripts
- `setup_test_suite.py` — adapted from test_for_ptoas: auto-generate run_<kernel>/golden.py stubs
- `setup_main.py` / `setup_vpto.py` — adapted from test_for_ptoas (onboard mode, VMI+membar+vf-off flags)
- `setup_all.sh` — orchestrator

### Step 5: Write `run_all.py`
- Loop over all 101 kernels
- For each: `cd run_<kernel>/vpto && bash run.sh` (golden → ptoas → bisheng → NPU → compare)
- Serial on one device (avoid daemon socket conflict)
- Collect result.json → aggregate CSV

### Step 6: Write `compare_results.py`
- Read all result.json → summary CSV + stdout table

## Key design decisions

1. **torch for golden** (not numpy) — matches DSV4 model golden_fn style, native bf16 support
2. **101 kernels in one shot** — multiple subagents in parallel, each writing ~15-20 build_ functions
3. **Reuse vpto_run.py --golden-lib mode** — already supported, no changes to the skill needed
4. **VMI+membar+vf-off route** — run.sh uses the 7 bisheng -mllvm flags + ptoas VMI flags
5. **No GM dump dependency** — golden generated on CPU, inputs are random, completely bypasses P0 bug
6. **validation_runtime.py reused** — load_case_meta, rng, write_buffers, write_golden all reused from test_for_ptoas

## What NOT to do (scope limits)
- No modifying pypto/ptoas/pto-isa — read-only
- No modifying model .py files — read-only (we reference them for golden logic but don't modify)
- No modifying vpto_run.py — it already supports --golden-lib mode
- No EmitC route — VMI-only as requested
